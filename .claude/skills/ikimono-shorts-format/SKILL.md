# 生き物・雑学ショート フォーマット

見た目の仕様（画面の4段構成、色、文字サイズ）は `basuta-shorts-format` と同じ。このスキルではジャンル固有のルールだけ定める。

## 1. 投稿の比率
- **生き物：雑学・科学 ＝ 3：1**（例：週4本なら生き物3本、雑学1本）
- 雑学・科学は「宇宙・地球・人体」など、生き物と同じく **「強すぎる／やばすぎる」で断言できて数値で語れるネタ** に限る。
- チャンネル名：「生き物解説ch」

## 2. タイトル
```
【ガチ解説】{生き物/対象}の{能力}が{強すぎる|やばすぎる|速すぎる|硬すぎる}{（三選）} #生き物 #動物 #雑学 #shorts
```
- 雑学回のハッシュタグは `#雑学 #宇宙 #科学 #shorts` などに差し替える。
- 能力は1つに絞る（パンチ、生命力、スピード、毒、顎の力など）。

## 3. 冒頭3秒（0〜3秒）
**「格付けの一言。」＋「{対象}の{能力}が{〜すぎる}。」** の2文で言い切る。
- 格付けの例：「動物界最速。」「地球最強の生命力。」「宇宙一重い。」
- 最初の1秒目に、その能力がいちばん伝わる映像を置く（パンチの瞬間、急降下など）。

## 4. 台本の構成（45〜50秒）
| 時間 | 内容 | 上段（固定） | 中段 | 下段字幕 |
|---|---|---|---|---|
| 0〜3秒 | 断言 | 3行の煽り | いちばん派手な映像 | 冒頭のセリフ |
| 3〜35秒 | 根拠を3つ（1つ約10秒） | 同上 | 映像＋赤い数値テロップ | 解説 |
| 35〜45秒 | 身近なものとの比較で締め | 同上 | 比較の図 | 「つまり〜なのだ。」 |
| 45〜48秒 | 次回への引き（任意） | 同上 | — | 「次は〇〇を解説するのだ。」 |

- ナレーションは VOICEVOX ずんだもん（語尾は「〜のだ」）。概要欄に「VOICEVOX:ずんだもん」と書く。
- **数値は必ず身近なものに置き換える**（例：「体重の約2,500倍」「新幹線並み」）。

## 5. テロップ（basuta-shorts-format を流用）
- 上段：1行目と2行目は黄 `#FFFF00`、3行目は赤 `#E60000`（いちばん大きく、約190〜200px）。
- 下段：白文字に緑 `#48B068` の縁取り、丸ゴシック、約70〜80px、3行以内。
- 中段の数値：赤＋黒縁で約100px。単位まで入れる（例「時速389km」）。

## 6-A. AIっぽさを消すルール
- **中段は本物の写真や映像が主役**。図形だけのアニメは使わない（使うとしても補足に限る）。
- **字幕1枚ごとにカットを切り替える**。写真は毎カット、ゆっくりズーム・パン（`zoom` / `focus` / `pan`）。ズームの向きはカットごとに変える（寄る→引く→寄る）。
- **注目させたい部位は手描き風の赤丸で囲む**（`circle`）。きれいな正円にしない。
- **数値テロップは±3〜5度傾けて、ポンと出す**（`label` の `angle`）。全部同じ角度にしない。
- **台本は話し言葉**。全部の文末を「〜のだ」にしない（「〜らしい」「ずるくない？」「意味がわからないのだ」など、ツッコミや感想を混ぜる）。
- 冒頭は格付けの決まり文句より、**具体的な一言**（「このシャコ、パンチで貝殻を叩き割るのだ。」）のほうが自然。
- 出典を確認できない数値は使わない（言い換えるか削る）。

## 6-B. 図解とパンチ演出（script.json の shot に書く）
- `overlay`：写真の上に半透明パネルで図解を重ねる。`speed_chart`（速さの棒グラフ）、`shell_crack`（貝殻が割れる図）、`bubble_steps`（泡で2発目が入る3ステップ）、`two_peaks`（衝撃グラフ・イメージ図）、`glass_crack`（画面全体のヒビ）。新しいネタでは make_short.py に `ov_*` 関数を足して `OVERLAYS` に登録する。
- `clip`：`assets/` に置いた動画（例 `punch.mp4`）を中段に流す。ファイルがなければ写真で代用する。
- `punch`：写真でパンチの瞬間を再現する（急ズーム→揺れ→白フラッシュ→衝撃線→「ドンッ！」）。冒頭3秒に使う。
- 推定のグラフには「※イメージ図」と必ず入れる。

## 6. 素材（映像）のルール
- **写真の取得先は iNaturalist**（APIキー不要）。`photo_license=cc0,cc-by` で絞り込む。CC BY-SA と NC（非営利限定）は使わない。
  - Wikimedia Commons は、この環境からだと画像の取得に制限がかかる（429エラー）。
- **動画の取得先は figshare**（論文の付録動画。多くが CC BY 4.0 で、APIキー不要）。`https://api.figshare.com/v2/articles/search` に `{"search_for": "<英名>", "item_type": 2}` を送って探し、記事ごとに `license` を確認する。
  - 長い動画から、ffmpeg のシーン変化スコアで動きの大きい箇所を探す。ただしカメラのパンも引っかかるので、必ずコマ送りで本物の動作か確かめる。
  - 打撃の瞬間だけスロー（0.25〜0.3倍）にした3〜4秒のクリップを `assets/punch.mp4` にし、`clip_hit`（クリップ内で当たる秒数）を指定すると、そのコマに合わせて衝撃演出が入る。
  - 切り出しやスローは改変にあたるので、クレジットに「一部を切り出し・スロー加工」と書く。
- 取得した写真は `shorts/<ネタ名>/assets/` に置き、`credits.json` に撮影者・ライセンス・出典URLを記録する。生成ツールが画面右下に小さくクレジットを出し、概要欄にも全員分を自動で書き出す。
- 撮影者の透かしが入った写真は、切り抜き（`focus` / `zoom`）で画面の外に出す。
- 収益化するので、**商用利用できる素材だけを使う**：自分で撮った映像、Pexels や Pixabay などのフリー素材（毎回ライセンスを確認する）、自作のイラストや図。
- テレビ番組、他人の YouTube 動画、図鑑のスキャンは使わない。
- 量産テンプレと判断されないよう、**毎回オリジナルの比較図か独自のまとめを1つ以上入れる**。

## 7. ファクトチェック（必須）
- 数値は **論文、博物館、大学、公的機関など信頼できる出典を2つ以上** 確認してから使う。
- 諸説ある数値は「〜とも言われる」「記録では」と言い方をぼかす。
- 出典は概要欄に1行で書く（信頼性が上がり、コメント欄での指摘も減る）。

## 8. ネタ帳（タイトル案）
生き物（メイン）
1. 【ガチ解説】シャコのパンチが強すぎる → 例：`examples/shako.md`
2. 【ガチ解説】クマムシの生命力がやばすぎる（宇宙空間に置かれても生き延びた個体がいる）
3. 【ガチ解説】ハヤブサの急降下が速すぎる（記録では時速389km）
4. 【ガチ解説】テッポウエビのハサミがやばすぎる（泡がはじける瞬間、数千℃になるとも言われる）
5. 【ガチ解説】イリエワニの噛む力が強すぎる（実測では動物トップクラス）
6. 【ガチ解説】ベニクラゲが不老不死すぎる（若い姿に戻れる）
7. 【ガチ解説】ミイデラゴミムシのおならがやばすぎる（約100℃の噴射）
8. 【ガチ解説】ラーテルが怖いもの知らずすぎる

雑学・科学（ときどき）
9. 【ガチ解説】中性子星が重すぎる（角砂糖1個分で約10億トンとも言われる）
10. 【ガチ解説】金星の環境がやばすぎる（地表は約460℃、気圧は地球の約90倍）

※ かっこ内は台本の方向性。数値は 7. の手順で確認してから使うこと。

## 9. 動画の生成（tools/shorts/make_short.py）
1. `shorts/<ネタ名>/script.json` を作る（`shorts/shako/script.json` をコピーして書き換える）。
   - `text`：画面に出す字幕。`\n` で改行位置を指定できる（1枚3行まで）。
   - `yomi`：VOICEVOX に読ませる文（「23m」→「23メートル」のように読みを直す）。
   - `visual`：中段の図解アニメ（hook / speed / force / bubble / glass / next）。新しいネタでは make_short.py にシーン関数を追加する。
2. `python3 tools/shorts/make_short.py shorts/<ネタ名>` を実行する → `out/short.mp4`（この段階では音声なし）、`out/voicevox_import.txt`、`out/description.txt` が出る。
3. VOICEVOX で `voicevox_import.txt` を「テキスト読み込み」し、ずんだもんを選んで（話速1.1前後）、**1行ずつ** `01.wav`, `02.wav`… と書き出し、`shorts/<ネタ名>/voice/` に入れる。
4. もう一度実行すると、音声の長さに合わせて字幕が切り替わる音声入りの完成版になる。
5. BGM や効果音を足すなら、完成した mp4 を編集ソフトに読み込んで重ねる（音源は商用利用できるものを使う）。
